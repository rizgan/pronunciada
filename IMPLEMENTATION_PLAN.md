# Английское произношение · меньше ложных отметок на звуках

## Цель и способ принятия решения

Рабочая точка — английский, sensitivity=balanced, strictness=0.5, публичный вызов SentenceResult.coaching() без лимита items. Ученик читает заданный текст. Отметка — уникальная пара (word_index, phone_index) с kind равным substitution или missing. Название услышанного звука для попадания не требуется. Правильный результат — меньше отмеченных экспертами как правильные звуков при сохранении доли найденных экспертных ошибок. Скорость отложена.

Основной корпус — speechocean762. Ошибка по разметке — phones_accuracy < 2. Считать по всем сопоставленным звукам с конечной оценкой, включая звуки в пропущенных словах. Если на звук нет отметки, предсказание отрицательное. Единица сравнения версий — (id записи, индекс слова эксперта, индекс звука эксперта). Фиксировать TP, FP, FN, TN, precision=TP/(TP+FP), recall=TP/(TP+FN), число записей, дикторов, сопоставленных и пропущенных звуков. Нельзя улучшать результат исключением сложных записей.

Исторический ориентир — precision 65,883%, recall 36,215%, 47 041 звук (results/tables/coaching_azure_yardstick.json). Там bench/coach/azure_yardstick.py:main берёт error_prob до исключения пропущенных слов и пересекает выборку с кешем Azure. Новая база — реально выданные отметки текущей сборки на всём доступном официальном split. Цифры могут различаться. Azure не нужен. Выделять отдельно сырую маску детектора и итоговые отметки. Текстовые tips с ограничением max_tips=3 — вспомогательный отчёт. Изменение фильтра tips, общего strictness, оценок слова или порога отображения не решает задачу.

**Приёмка на официальном test:** на идентичном наборе ключей FP строго меньше, TP не меньше, нижняя граница парного 95% интервала прироста precision выше нуля. Интервалы для обеих разностей считать по дикторам (1000 парных повторов с возвращением, seed 0). Для recall требуется неотрицательная наблюдаемая разность, интервал публикуется как мера неопределённости. +3–5 процентных пунктов precision — ориентир, указать отдельно, достигнут ли. Датасет охватывает учащихся с мандаринским родным языком. До фиксации кандидата использовать только train. Один итоговый просмотр test для этой гипотезы.

## Эпоха 2 — проверить поправку по классам фонем на train

**Вход:** принята эпоха 1, доступны отчёт, измеритель и ключи. **Выход:** один замороженный кандидат только для en/balanced либо воспроизводимое решение отклонить его. Продуктовая конфигурация в этой эпохе ещё исходная.

1. Проверяем одну гипотезу: при одинаковом error_prob некоторые классы ожидаемых звуков дают больше ложных тревог. Перераспределить отметки между классами при том же количестве найденных ошибок. Использовать существующий coach.sound_class, без нового энкодера и без смены выравнивания. Результаты по соседям пропущенного слова в results/round20_native_fa.md относятся к словам и искусственным пропускам. Они не доказывают причину ложных отметок на звуках учеников.
2. Для подбора использовать train-признаки вне обучающей складки (OOF). В bench/coach/fit_v2.py:so762_rows смотри замену zl/zs на OOF-логиты английского detail-калибратора из calib/sound_oof.parquet, а в fit_logistic и oof — обучение и GroupKFold по speaker. Сверь словарь признаков с текущим by_lang.en.sound_model. Для оценки гипотезы получи базовый coaching score тоже вне складки, переобучая исходную логистическую голову только на обучающих дикторах. Обеим системам дай одинаковые базовые scores и правила omitted. Не обучайся на in-sample вероятностях из отчёта эпохи 1. Используй bench/coach/dump.py и инструкции bench/calib/train_sound_emb.py для кеша. Проверяй полное покрытие (utt, phone_index), путь и версию признаков. so762_rows может молча пропускать записи без OOF. Артефакты другого запуска используй только после проверки совместимости. Не запускай fit-команды, перезаписывающие поставляемые модели.
3. На внутренних обучающих предсказаниях подбери добавку к logit базовой вероятности для каждого sound_class: логистическая модель с коэффициентом базового logit, фиксированным в 1, и L2-штрафом на классовые поправки (сумма log-loss + 0.5 * сумма квадратов поправок). Вероятности перед logit ограничь [1e-6, 1-1e-6]. Для отсутствующего класса поправка 0. Один общий порог на скорректированный logit выбери по train: максимальная precision при TP >= исходного TP и FP < исходного FP; при равенстве выбери больший TP, затем больший порог. Сравнение >=, одинаковые scores включай вместе. Экспортируй эквивалентные пороги на **исходной** шкале error_prob для классов и fallback = sigmoid(общий порог). Это сохраняет шкалу уверенности, используемую для ранжирования. Если допустимого порога нет, кандидат отклонён.
4. Внешние пять складок по дикторам оценивай после подбора поправок и порога на остальных дикторах (внутренние OOF для подбора). Публикуй объединённые TP, FP, precision, recall и парные интервалы. Отдельно укажи происхождение ранее обученных компонентов и ограничения такой оценки. В финальную проверку допускай лишь при FP ниже и TP не ниже на объединённых внешних прогнозах. При допуске повтори подбор на всех train OOF и сохрани конечные пороги, fallback, SHA базы и хеш кандидата в results/tables/en_precision_candidate.json. В противном случае сохрани отрицательный отчёт, заверши эксперимент на train и отметь эпоху 3 неприменимой. Test при этом остаётся доступен для следующей согласованной гипотезы.
5. Проверь применение замороженного правила через bench-обвязку на train-записи из эпохи 1 или другом идентифицированном примере: старая версия отмечала верный звук, кандидат снимает эту отметку; приведи контрольный TP, который остаётся отмеченным.
